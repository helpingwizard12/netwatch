What information does Netwatch show, and what can't it see?
Per packet
  • Time (µs), direction (in/out), network interface (en0 Wi-Fi, utun VPN…)
  • App name + PID that owns the socket (from the macOS kernel), and the app it acts on behalf of
  • Source/destination IP and port, MAC addresses, size on the wire
  • IP details: TTL/hop limit, IP ID, flow label, DSCP/ECN, fragments
  • TCP: flags (SYN/ACK/FIN/RST/PSH), sequence & ack numbers, window, MSS/options
  • UDP length, ICMP type (ping, unreachable, neighbor discovery), ARP who-has
  • First 256 bytes of payload as a hex dump
Decoded from the unencrypted parts
  • DNS / mDNS: every name looked up and the IPs returned → used to name remote hosts
  • TLS: the website name (SNI), ALPN (h2/http1.1), TLS version & cipher
  • QUIC/HTTP-3: version and packet type; plain HTTP: request line, Host, User-Agent
  • DHCP (your IP, router, DNS servers), NTP, SSDP/UPnP device announcements
  • Grouped: connections (bytes each way, state, who initiated), apps (live rate), remote hosts with approximate owner (Google, Cloudflare, Apple…)
Worth a look (rule-based hints, not proof)
  • App with a macOS system name not signed by Apple; unsigned or odd-location apps (temp, Downloads, disk images)
  • Incoming connections from the internet; ports used by remote-access/proxy tools; unusual ports
  • Connections to unnamed IPs outside known providers; apps uploading far more than they download
  • Clockwork-regular check-ins; DNS to unusual servers, very long names, failed random-looking names
Not visible
  • Contents of HTTPS / QUIC / VPN traffic — it is encrypted end to end
  • Names for hosts reached via encrypted DNS (DoH) or QUIC, unless seen elsewhere
